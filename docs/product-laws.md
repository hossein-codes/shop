# منشور محصول نَخ — قوانین دوازده‌گانه الزامی

> **وضعیت:** ✅ مصوب کارفرما (۲۰۲۶-۰۸-۲۲) — لایه‌ی بالادستی همه‌ی تصمیم‌ها  
> **دامنه:** تمام طراحی‌ها، کامپوننت‌ها و صفحات — بدون استثنا  
> **قرارداد اجرا:** پیش از ساخت هر صفحه یا کامپوننت جدید، چک‌لیست همین سند اجرا می‌شود. هر تصمیم مخالفِ قانون‌ها = توقف و ارائه‌ی پیشنهاد بهتر به کارفرما.

این منشور با سه سند موجود رابطه‌ی سلسله‌مراتبی دارد:

```
منشور ۱۲ قانونی (این سند)   ←  «آیا درست است؟»
   ↓
Design System v1.2           ←  «چگونه ساخته می‌شود؟»
   ↓
سند محصول (Blueprint)       ←  «چه چیزی و کِی؟»
```

## قانون ۱ — کاربر همیشه اولویت دارد

**آزمون هر تصمیم:** «آیا این کار باعث می‌شود کاربر سریع‌تر، راحت‌تر و با اطمینان بیشتر خرید کند؟»
عنصری که فقط زیبا است و پیچیدگی می‌آورد → حذف.

- ✅ ❌ الگوی درست: یک Hero واضح با یک پیام و یک CTA — نه چند اسلایدر نمایشی.

| معیار پذیرش | وضعیت فعلی |
|---|---|
| هر نما یک قهرمان و یک پیام اصلی دارد | DS §۱.۴ و §۸ سند محصول (Hero تک‌پیام) ✅ |
| «سه کلیک تا خرید» به‌عنوان سنجه طراحی | DS اصل ۲ ✅ |

## قانون ۲ — سرعت و عملکرد

سایت باید حس اپلیکیشنِ سریع داشته باشد؛ کاربر منتظر نمی‌ماند.

- منوها بازشدن سریع و روان · تغییر صفحه بدون حس تأخیر · تصاویر بهینه
- Loading State حرفه‌ای + **Skeleton Loading** · حذف درخواست‌های غیرضروری

| معیار پذیرش | وضعیت فعلی |
|---|---|
| Skeleton برای لیست/کارت | `Skeleton` + `ProductCardSkeleton` ✅ |
| دکمه‌ها حالت Loading با عرض قفل | `Button loading` ✅ |
| بدون صفحه سفید — مینی‌کارت به‌جای ریدایرکت | `Drawer` ۳۰۰ms ✅ |
| تصاویر `next/image` + sizes + lazy | `ProductCard`/`CategoryCard` ✅ |
| فونت `font-display: swap` + فالبک هم‌متریک | `globals.css` ✅ |
| LCP < 2.5s · CLS < 0.1 (سنجش در هرRelease) | سند محصول §۱۵ — پایش در فاز صفحات ⏳ |

## قانون ۳ — سادگی در تعامل

هر کار کاربر = کمترین مرحله‌ی ممکن.

- الگوی الزامی دسترسی: پروفایل → Dropdown → «سفارش‌های من» (نه منوی چندلایه).
- OTP بدون رمز · Checkout تک‌صفحه‌ای · حذف از سبد بدون رفرش.

| معیار پذیرش | وضعیت فعلی |
|---|---|
| مسیرهای اصلی ≤ ۳ اقدام | DS اصل ۲ ✅ |
| OTP با Paste + تأیید خودکار | `OtpInput` ✅ |

## قانون ۴ — طراحی Mobile First

طراحی ابتدا برای موبایل بررسی می‌شود (۸۰٪+ کاربران).

- دکمه‌های مناسب لمس (≥۴۴px) · عناصر مهم در دسترس انگشت (Bottom Navigation) · صفحه غیرشلوغ · دکمه خرید بزرگ و همیشه در دسترس

| معیار پذیرش | وضعیت فعلی |
|---|---|
| هدف لمسی ≥ ۴۴×۴۴ | همه‌ی کامپوننت‌ها (حتی سواچ/قلب) ✅ |
| Bottom Nav + نوار خرید چسبان | DS §۸.۲/§۶.۹ — ساخت در فاز صفحات ⏳ |
| CSS موبایل‌اول (min-width) | DS §۴.۱ ✅ |

## قانون ۵ — طراحی برند Fashion

سایت نباید شبیه فروشگاه عمومی باشد: فضای سفید، تصاویر بزرگ، تایپوگرافی قوی، فاصله‌های مناسب، مینیمال، حرکت‌های ظریف.

- الگوی درست: یک داستان بصری برای کالکشن جدید — نه ۱۰ بنر تخفیف.

| معیار پذیرش | وضعیت فعلی |
|---|---|
| مسیر بصری A+B قفل | DS §۱.۳ ✅ |
| سقف بنر تخفیف در صفحه اصلی | سند محصول §۸ (حداکثر ۱ نوار اعلان) ✅ |

## قانون ۶ — عدم شلوغی

هر صفحه فقط یک هدف اصلی دارد.
صفحه محصول = خرید: تصویر، قیمت، سایز، رنگ، خرید — بدون عناصر حواس‌پرتی.

| معیار پذیرش | وضعیت فعلی |
|---|---|
| PDP بدون ویجت اضافه بالای فولد | DS §۹ ✅ |
| حداکثر ۲ بج روی کارت | `Badge` + DS §۵.۶ ✅ |

## قانون ۷ — اعتمادسازی

## قانون ۱۰ — وضعیت‌های کامل

هیچ بخشی فقط حالت موفق ندارد. هر کامپوننت: **Loading · Empty · Error · Success · Disabled**

- سبد خالی = پیام مناسب + تصویر ساده + پیشنهاد ادامه خرید (نه صفحه‌ی خالی).

| معیار پذیرش | وضعیت فعلی |
|---|---|
| Loading | `Skeleton` / `ProductCardSkeleton` / `Button loading` ✅ |
| Empty | `EmptyState` (پیام + تصویر + اقدام) ✅ |
| Error (داده/شبکه) | `ErrorState` (افزوده در این نسخه) ✅ |
| Success | `toast.success` + `FreeShippingProgress` حالت رسیده ✅ |
| Disabled | `Button/Input/Select/SizeChip/QuantityStepper` ✅ |
| کارت محصولِ ناموجود | `ProductCard soldOut` (افزوده در این نسخه) ✅ |
